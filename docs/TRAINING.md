# TRAINING — standing directives, general findings, required logging

**Read this before launching or interpreting any training run** (SA3/SAME LoRA/DoRA/full-FT, LatCH heads, control adapters, optimizer or LR brackets).

*Built 2026-10-07 by THE-FINN at WINTERMUTE's request (Kim: "a directive pointing to a training.md where we record directives and general findings"). It is an INDEX of rules and cross-run findings, each with a pointer to the evidence. It does not repeat the dated log: **`docs/training-findings.md` is the chronological log** (postmortems, A/B/C failure catalogue) that this file cites. Operator manual for the modular trainer: `docs/train_lora_modular.md`. Facts that silently give wrong results (EMA, GPU lock, venvs): `.claude/skills/sa3-training/SKILL.md`. Experiment registry: `EXPERIMENTS.md`.*

**How to use it.** §1 = rules (do / don't), each with a one-line why. §2 = what holds across runs, with confidence. §3 = what a run must record. §4 = open items and known discrepancies. When a rule here and a source disagree, the SOURCE wins and this file is wrong: fix it (owner: THE-FINN with the training owner; see `OWNERSHIP.md`).

**Confidence key.** **High** = mechanism understood or measured with a margin well above the noise floor. **Medium** = measured, but one run, one seed, or a reading that rests on a single comparison. **Weak** = single seed inside the noise floor, an ear verdict not yet backed by a measurement, or secondhand. **Prelim** = Kim's ear, not yet audited.

## 3. REQUIRED LOGGING — per run

**Why this section exists (the gap).** MASTER §4 (2026-06-24) already makes full tiered telemetry a STANDING REQUIREMENT for control-head runs ("you can't backfill"). It was not applied: **LatCH Phase D (16 arms) kept only a 94-line `train.log` per arm (per-epoch train/val) and the epoch checkpoints.** `latch/train_latch.py` has a `--wandb` flag (default off) and `run_modular_bracket.sh` does not pass it, so there is no per-step loss, grad norm, LR or trajectory for any arm, and the checkpoints (per W) store `val_loss` but not lr/schedule. The Phase D trajectory question (does b32 differ at equal steps? when does dim 512 pull ahead?) then had to be answered from 10 numbers per arm.

**Rule: every run, local or LUMI, any trainer, records the following. Nothing here is optional because the run is "just a bracket".**

## 4. OPEN ITEMS and KNOWN DISCREPANCIES between sources

**Discrepancies (sources disagree or leave a gap; each wants an owner decision):**
