# Animation module `qkv-line`: contract for three parallel tracks

Owner: WINTERMUTE (created 2026-10-27). Spec: `docs/superpowers/specs/2026-10-26-help-pane-design.md` section 7, row `qkv-line`.
Used by the glossary entries `qkv` and `fused-matrix` (`glossary/model-parts.json`, CONTINUITY's file: read only).
Reference module for style and structure: `site/help/viz/batch-noise.js` (and its tests). Shared helpers: `lib/kit.js`,
update maths: `lib/optim.js` (`newtonSchulz5`, `matmul`, `frobenius`, ...), seeded random numbers: `lib/noise.js`
(`mulberry32`, `makeGauss`, `randnMatrix`).

## What the reader sees

Two scenes, chosen with two buttons:

**Scene 1, "Making Q, K, V" (an assembly line).** An input (one position's numbers, a row of `d` = 4 small cells) rides a
conveyor into the machine room and comes out as three packets labelled Q, K and V. A second pair of buttons picks the room:
- "One fused machine": one wide machine, labelled "stacked matrix, 12 × 4", stamps all three packets in one go.
- "Three machines": three machines side by side, each labelled "4 × 4", each stamps one packet.
Packets keep riding in a loop (a new input every ~2 s). Readouts: the largest difference between the fused and the separate
outputs for the current input (computed live; it is 0 or ~1e-16), and a line saying what each room does:
"1 multiplication by a 12 × 4 matrix" vs "3 multiplications by 4 × 4 matrices", plus "Same numbers out; the fused one is
faster on a GPU because it is one call."

**Scene 2, "Orthogonalising the step".** Muon replaces each matrix's gradient by an orthogonalised version (Newton-Schulz,
5 steps). Two bar groups side by side, each with three bars Q, K, V = the size of the step each block gets (RMS per weight of
the orthogonalised gradient):
- "Stack orthogonalised as one" (what our trainer did, marked "ours" next to the title);
- "Each orthogonalised on its own" (what the Muon post recommends).
A slider "Key gradient strength" (7 stops: 0.01, 0.03, 0.1, 0.3, 1, 3, 10, default 1) multiplies the K block of the gradient.
Bars ease to their new height (~300 ms) when it moves. Separate: Q and V do not move at all, K stays the same size too
(orthogonalisation removes scale). Stacked: a strong K squeezes Q and V; a weak K gets almost no step. A readout states it in
numbers: "Stacked: the query step is <x>% of its size at strength 1. On its own: 100%."

## Track A: maths (`site/help/viz/lib/qkv.js` + `site/help/viz/tests/qkv.test.mjs`)

Pure functions, no DOM. Imports only from `./optim.js` and `./noise.js`. Exports, exactly:

```js
export const QKV = { d: 4, seed: 7 };
export const KSCALES = [0.01, 0.03, 0.1, 0.3, 1, 3, 10];
export function stack(A, B, C)          // rows of A, then B, then C (a [3d x d] matrix from three [d x d])
export function split(M)                // inverse of stack: [A, B, C], each M.length / 3 rows; throws if not divisible by 3
export function makeWeights(seed = QKV.seed)   // { Wq, Wk, Wv }, each d x d, randnMatrix with makeGauss(mulberry32(seed)), drawn in that order
export function makeInput(seed)               // array of d numbers from makeGauss(mulberry32(seed)) (the module uses seed = 100 + input count)
export function projectFused(W, x)      // W = { Wq, Wk, Wv }: one matmul of stack(Wq, Wk, Wv) with x as a column; returns { q, k, v } (arrays of d)
export function projectSeparate(W, x)   // three matmuls, one per block; returns { q, k, v }
export function maxAbsDiff(a, b)        // a, b = { q, k, v }: largest |a[i] - b[i]| over all three
export function makeGrads(seed = QKV.seed + 1)  // { Gq, Gk, Gv }, each d x d, drawn like makeWeights
export function rms(M)                  // frobenius(M) / sqrt(rows * cols)
export function orthSizes(G, kscale)
  // G = { Gq, Gk, Gv }. The K block is multiplied by kscale first.
  // -> { fused: [q, k, v], separate: [q, k, v] }
  // fused: split(newtonSchulz5(stack(Gq, kscale*Gk, Gv))).map(rms)
  // separate: [Gq, kscale*Gk, Gv].map(M => rms(newtonSchulz5(M)))
  // No Muon scale factor (muonScale) is applied: the bars compare directions only, and the note says so.
```

Node tests (`node --test site/help/viz/tests/`), each a real check:
1. `split(stack(A, B, C))` returns A, B, C exactly; `split` of a 5-row matrix throws.
2. `maxAbsDiff(projectFused(W, x), projectSeparate(W, x)) < 1e-12` for 10 different input seeds.
3. Separate sizes do not depend on kscale: the q and v entries are identical (`===`) at every KSCALES value, and k is within 1e-6 of its value at 1.
4. Coupling: fused q at kscale 10 is less than 0.3 x fused q at kscale 0.01; same for v.
5. Starvation: fused k at kscale 0.01 is less than 0.05 x separate k.
6. Determinism: `makeWeights(7)` twice is identical; `makeWeights(8)` differs.
7. Every size at every KSCALES value is finite and > 0.
Measured with the reference code on 2026-10-27 (seed 7 stream, Q/K/V drawn in order): fused q 0.373 at 0.01 -> 0.056 at 10;
separate about 0.41-0.51 for all. If 4 or 5 does not hold with these constants, report it with the numbers; do not tune
constants silently.

## Track B: the module (`site/help/viz/qkv-line.js`)

Follows `batch-noise.js` in style: `mount(container, params, help) -> { destroy() }`, CSS injected once with `injectStyle`,
colours from `help.colors` via `applyColors`, `loop()` from `lib/kit.js` (pauses out of view; with `help.reducedMotion`
nothing moves until the Step button; one Step = the next input's packets appear at their end positions in scene 1, the bars
jump to their targets in scene 2), `realNote()` required. Imports only from `./lib/`. Rules from `lib/kit.js`: never name a
colour in text (the Q, K, V packets and bars are told apart by their letters and by swatches); `help.openTerm` only for ids in
the qkv / fused-matrix entries' text (it is fine not to call it at all).

DOM contract (track C tests against it; do not rename):
- root `div.vz-qkv` with `data-scene` (`make`|`orth`), `data-mode` (`fused`|`separate`), `data-kscale` (the number, e.g. `1`),
  `data-inputs` (how many inputs have entered the line so far; starts at 1 and grows while scene 1 plays).
- a `role=group` labelled "Scene" with buttons "Making Q, K, V" and "Orthogonalising the step", `aria-pressed`.
- scene 1 panel `div.vz-qkv-make` (has the `hidden` attribute while scene 2 shows), containing:
  - a `role=group` labelled "Machines" with buttons "One fused machine" and "Three machines", `aria-pressed`;
  - `svg.vz-line` with `g.machine` elements (exactly 1 when fused, 3 when separate) and packets `g.packet` with class `q`, `k`
    or `v` (each packet carries its letter as SVG text);
  - readouts `#vz-qkv-diff` (the largest difference, as a number) and `#vz-qkv-ops`.
- scene 2 panel `div.vz-qkv-orth` (has `hidden` while scene 1 shows), containing:
  - `input#vz-qkv-kscale[type=range]`, min 0, max 6, step 1 (index into KSCALES), `<label for>` "Key gradient strength",
    `aria-valuetext` "key gradient × <n>"; `output#vz-qkv-kscale-out` shows the number;
  - `svg.vz-bars` with exactly six `rect.bar`, each with `data-block` (`q`|`k`|`v`) and `data-how` (`fused`|`separate`), and
    `data-size` = the size it is heading to (the value from `orthSizes`, full precision);
  - readouts `#vz-qkv-fused`, `#vz-qkv-sep` (the three sizes as text, 2 significant digits) and `#vz-qkv-change` (the
    "<x>% of its size at strength 1" sentence).
- the "What's real here" note (via `realNote`).
Defaults: scene `make`, mode `fused`, kscale 1. `params` may override: `{scene: 'make'|'orth', mode: 'fused'|'separate',
kscale: <one of KSCALES>}`; invalid values fall back to the defaults. Changing the room restarts the line (data-inputs back to 1).
The loop goes idle in scene 2 once the bars have arrived, and resumes on a slider change or a scene switch.
Works at 360 px wide (no horizontal overflow): at narrow widths the three machines may stack or shrink, the bar groups may
stack.

"What's real here" content:
- Computed live: the three outputs both ways, and their difference; both orthogonalisations (5 Newton-Schulz steps with
  Muon's coefficients) on 4 × 4 blocks, at the chosen key gradient strength.
- From our own runs: no numbers. Our heads store Q, K and V as one stacked matrix, and a routing check of our heads
  (2026-10-17) found that our optimizer orthogonalised that stack as one matrix. What that did to training is not measured.
- Illustration only: the matrices are random and 4 wide (real blocks are 256 wide); the gradient strengths are chosen for the
  picture; the bars leave out Muon's shape-based scale factor, which also differs between a 12 × 4 stack and a 4 × 4 block.

For local testing before track A lands, Track B may write a stub `lib/qkv.js` that follows the contract above, but must NOT
commit it (only `qkv-line.js` is committed).

## Track C: browser tests (`site/help/viz/tests/test_qkv_line_browser.py`)

Use `from vizbrowser import open_page` (never `from conftest import ...`); fixtures `browser` and `base_url` come from
`site/help/viz/tests/conftest.py`. Tests against the DOM contract (`dev.html?m=qkv-line`, params via `&p=<json>`):
1. Mounts with no console/page errors; scene 1 shows, 1 `g.machine`, the note "What's real here".
2. `data-inputs` grows within 3 s in scene 1 (animated).
3. "Three machines": `aria-pressed` flips, `data-mode=separate`, exactly 3 `g.machine`, `data-inputs` back to 1; the diff
   readout parses to a number < 1e-9 in both rooms.
4. Scene switch: "Orthogonalising the step" shows `.vz-qkv-orth` and hides `.vz-qkv-make` (`hidden`), `data-scene=orth`.
5. Slider: index 6 (strength 10) -> fused q `data-size` is less than at index 4 (strength 1); separate q `data-size` is equal
   at both (string equality); `data-kscale` follows; `#vz-qkv-change` contains a percentage below 100.
6. `&rm=1`: `data-inputs` stays 1 for 1 s; clicking "Step" raises it.
7. After `window.__viz.destroy()`, no requestAnimationFrame callbacks are outstanding (RAF_SPY) and the root is gone.
8. Viewport 360 x 740, both scenes: `document.documentElement.scrollWidth <= clientWidth`.
9. Keyboard: Tab reaches the scene buttons; in scene 2 the slider takes ArrowLeft and `data-kscale` drops to the previous stop.
10. Params: `p={"scene":"orth","kscale":0.1}` starts there; `p={"kscale":5,"mode":"x"}` falls back to 1 and fused.
11. The note mentions "4 × 4" or "4 wide" and "not measured" (catches a later edit that drops the honesty lines).
Until track B lands these tests fail; that is expected. Verify the file collects (`pytest --collect-only`).
