# Animation module `routing`: contract for three parallel tracks

Owner: WINTERMUTE (created 2026-10-27). Spec: `docs/superpowers/specs/2026-10-26-help-pane-design.md` section 7, row `routing`.
Used by the glossary entries `adaln` and `parameter-group` (`glossary/model-parts.json`, CONTINUITY's file: read only).
Reference module for style and structure: `site/help/viz/qkv-line.js` and `batch-noise.js` (and their tests). Shared helpers:
`lib/kit.js`. Sources: `docs/TRAINING.md` F30, `docs/modular-opt-test-plan-2026-10-17.md` section P (the routing check), the
guide `blog/2026-10-21-muon-survival-guide-DRAFT.md` sections 3 and 4, and the trainer's own rules in
`stable-audio-tools/stable_audio_tools/training/modular_opt/routing.py` (another repo: read only; it is copied, not imported).

## The idea

Our optimizer decides which parameter goes to which group from the parameter's NAME (regular expressions) and shape. Our
heads use names the rules were not written for, so three kinds of parameter landed in the wrong place. The animation applies
the real rules, ported to JavaScript, to the real parameter names of one of our heads, and lets the reader switch to the names
the rules expect. The same rules then route everything as intended. That makes the point of the `parameter-group` entry:
print the groups at start-up and read them.

## What the reader sees

Two buttons: "Our head's names" (default) and "Names the rules expect".

A diagram of one of our heads (width 256, 2 blocks; one block is drawn, labelled "× 2"), as 11 rows from input to output:

| row id | label | parameters (real names) |
|---|---|---|
| `input` | Input projection | `latent_proj.weight` |
| `time1` | Time-embedding layer 1 | `t_embedder.mlp.0.weight` |
| `time2` | Time-embedding layer 2 | `t_embedder.mlp.2.weight` |
| `adaln` | AdaLN emitter | `blocks.N.adaLN_mod.1.weight` |
| `qkv` | Attention Q, K, V (stacked) | `blocks.N.attn.qkv.weight` |
| `attn-out` | Attention output | `blocks.N.attn.proj.weight` |
| `mlp-up` | MLP up | `blocks.N.mlp.0.weight` |
| `mlp-down` | MLP down | `blocks.N.mlp.2.weight` |
| `biases` | Biases (all layers) | every 1-D `*.bias` except `norm_final.bias` |
| `final-norm` | Final normalisation | `norm_final.weight`, `norm_final.bias` |
| `output` | Output layer | `out_proj.weight` |

On the right, three stations (optimizer groups), each with its name in text and a swatch: "Muon (orthogonalised)" =
`spectral`, "Sign step" = `sign`, "Column normalisation" = `colnorm`. Each row has a wire to the station its group says.
Gradients ride in along the wire as small dots, updates ride back; an update dot's size shows the step per weight
(log scale, one fixed scale for the whole diagram). When a parameter is split into blocks, its wire carries that many dots
side by side, each labelled (Q, K, V for the attention stack; 6 for the AdaLN emitter). Switching names re-routes the wires
(wires ease to their new station over ~400 ms).

Rows whose routing differs between the two views carry a text badge "differs" in BOTH views (computed, not typed): `time1`,
`time2`, `adaln`, `qkv`.

Each row is a button. Clicking or focusing one fills a detail panel: the real name(s) and, in the second view, the renamed
name(s); shape; group in this view; blocks; step per weight; and the row's note (below).

Readouts: `#vz-route-summary` = counts for this view, computed over all 28 parameters: "Muon: n, Sign step: n, Column
normalisation: n" (ours: 11 / 15 / 2; expected names: 11 / 17 / 0). Check these against the fixture.

## Track A: rules (`site/help/viz/lib/routing.js` + `site/help/viz/tests/routing.test.mjs`)

Pure functions, no DOM, no imports. Port of `routing.py` as of 2026-10-27, default arguments (`split_qkv=True`,
`split_adaln=True`, `scalar_opt='sign'`, no `force_sign`, `spectral_all=False`). Copy the five regular expressions verbatim
(`re.IGNORECASE` -> the `i` flag; `re.search` -> `RegExp.test`) and keep the rule order exactly. A comment names the source file
and date. Exports, exactly:

```js
export const HEAD_PARAMS   // [[name, [rows, cols]] or [name, [n]]], the 28 parameters of the head, in the order of
                           // site/help/viz/tests/routing_fixture.json "params" (copy them; do not import the JSON)
export const RENAME        // [['.attn.qkv.', '.attn.to_qkv.'], ['.attn.proj.', '.attn.to_out.'],
                           //  ['.adaLN_mod.', '.modulation.'], ['t_embedder.mlp.', 'time_mlp.']]  (same as the fixture)
export const MIN_SPECTRAL_DIM = 64;
export const GROUPS = ['spectral', 'sign', 'colnorm'];
export function renamed(name)                 // apply every RENAME pair (plain substring replace, in order)
export function inferAttentionDim(params)     // port of infer_attention_dim (params = [[name, shape], ...]); null if none
export function blockCount(name, shape, attnDim)   // port of get_block_count with split_qkv = split_adaln = true
export function route(params)                 // -> Map name -> { group, blocks, radius }; port of build_modular_param_groups'
                                              //    per-parameter loop (attnDim inferred from the same params, as in Python)
export function stepPerWeight({ group, blocks, radius }, shape, lr)
  // Arithmetic, per weight per step, before momentum and before our optimizer's row normalisation:
  // spectral: lr * radius / sqrt(max(rows / blocks, cols))   (an orthogonal [m x n] update has RMS 1/sqrt(max(m, n)))
  // sign:     lr * radius                                     (radius = 1/sqrt(cols) for 2-D, 1 for 1-D, as in routing.py)
  // colnorm:  null                                            (not worked out in the guide; the module says so)
export const ROWS          // the 11 rows of the table above: { id, label, names: [...] } with N expanded to 0 and 1
export function rowRouting(view)   // view 'ours' | 'expected' -> { [rowId]: { group, blocks, names, shape, step } }
                                   // a row's group/blocks are its parameters' (they agree within a row; throw if not;
                                   // the biases row: all sign/1), step = stepPerWeight at lr 1e-2 (the old recipe of guide
                                   // section 4); 'expected' routes renamed(name) for every parameter
export function differingRows()    // row ids whose group or blocks differ between the views
export function summary(view)      // { spectral: n, sign: n, colnorm: n } over all 28 parameters
```

Node tests (`node --test site/help/viz/tests/`), each a real check:
1. `route(HEAD_PARAMS)` equals the fixture's `ours` exactly (group and blocks) for all 28 names (read
   `routing_fixture.json` in the test with `fs`).
2. `route` of the renamed params equals the fixture's `expected_names` exactly.
3. Why `proj` must be renamed too: with only `.attn.qkv.` renamed, `inferAttentionDim` returns 768 (gcd of the two stacks) and
   the stack's block count is 1; with `to_out` present it returns 256 and the count is 3.
4. `differingRows()` is exactly `['time1', 'time2', 'adaln', 'qkv']` (any order); `summary('ours')` is 11/15/2 and
   `summary('expected')` 11/17/0 (or whatever the fixture gives: derive the expected counts from the fixture in the test,
   and also assert these literal numbers).
5. Step arithmetic at lr 1e-2: `attn.proj` (256 x 256, spectral) 6.25e-4; the stack whole (768 x 256, radius sqrt 3) 6.25e-4;
   the stack split in 3 also 6.25e-4 (the split changes directions, not size: say so in the module); a 1-D bias 1e-2; the
   output layer (1 x 256, sign) 6.25e-4; AdaLN emitter as sign (1536 x 256) 6.25e-4; `mlp.2` (256 x 1024) 3.125e-4; colnorm null.
   All within 1e-12 relative.
6. Rule order: a 2-D parameter named `x.modulation.embed.weight` routes to `sign` (AdaLN checked before embeddings); a 2-D
   `[32, 32]` hidden matrix routes to `sign` (below MIN_SPECTRAL_DIM).

## Track B: the module (`site/help/viz/routing.js`)

Follows `qkv-line.js` in style: `mount(container, params, help) -> { destroy() }`, `injectStyle`, `applyColors`, `loop()`
(pauses out of view; with `help.reducedMotion` the dots do not move: they sit at mid-wire and the Step button advances them by
one quarter of the wire), `realNote()` required. Imports only from `./lib/`. Rules from `lib/kit.js`: never name a colour in text
(stations and their wires are told apart by name text and swatches; the "differs" badge is text); `help.openTerm` only for
ids in the adaln / parameter-group entries' text (fine not to call it).

DOM contract (track C tests against it; do not rename):
- root `div.vz-route` with `data-view` (`ours`|`expected`), `data-selected` (row id, or empty), `data-tick` (an integer that
  grows while the dots move; stays put with reduced motion until Step).
- a `role=group` labelled "Names" with buttons "Our head's names" and "Names the rules expect", `aria-pressed`.
- `ul.vz-route-rows` with 11 `li`, each containing `button.vz-route-row` with `data-row` (row id), `data-group` (this view's
  group), `data-blocks` (number), `data-differs` (`yes`|`no`), `aria-pressed` (selected or not); the button text includes the
  label and, for differing rows, the word "differs".
- three `.vz-station` elements with `data-group` (`spectral`|`sign`|`colnorm`), each showing its name; in the expected view the
  colnorm station stays, showing "no parameters".
- `svg.vz-route-wires` (decorative, `aria-hidden="true"`) with one `path.wire` per row (`data-row`) and dots `circle.grad` and
  `circle.upd` (`data-row`, the update dot's `r` encodes the step).
- readouts `#vz-route-summary` and `#vz-route-detail` (`aria-live="polite"`, filled when a row is selected; empty or a hint
  ("Pick a row") otherwise).
- the "What's real here" note (via `realNote`).
Defaults: view `ours`, nothing selected. `params` may override: `{view: 'ours'|'expected', row: <row id>}`; invalid values fall
back to the defaults. The loop runs continuously while visible (dots are the animation); it never needs to go idle, but must
stop on destroy and pause out of view.
Layout: rows on the left, stations on the right, wires between. At 360 px wide: no horizontal overflow; the stations may move
above the rows as a horizontal strip and the wires may shorten; labels stay readable (at least 11 px).

Row notes (detail panel; plain words, shown in both views unless marked):
- `qkv`: "The rule splits a stacked attention matrix only if its name contains `to_qkv` (or `to_kv`, `to_q`), and it needs an
  output projection named `to_out` to know the width. Ours are called `qkv` and `proj`, so Q, K and V were orthogonalised as
  one matrix. Splitting does not change the step size here, only its direction (see the QKV entry)."
- `adaln`: "The rule sends AdaLN emitters to the sign step and splits them into their 6 pieces (shift, scale and gate, twice),
  but only if the name contains `modulation`. Ours is `adaLN_mod`, so it went to Muon whole. The guide's view that it should be
  split is reasoning, not a tested result."
- `time1`/`time2`: "Any 2-D name containing `embed` goes to column normalisation, the rule for input embedding tables. These
  are ordinary hidden layers that process the noise level; the rename `time_mlp` is our reading of what they should be."
- `input`: "Routed to Muon in both views. The Muon post sends embeddings to the second optimizer; whether an input projection
  counts as one is our reading (guide section 3)."
- `biases`, `final-norm`: "1-D parameters always take the sign step, which moves each one by the full learning rate: 16 times
  more per step than a 256-wide matrix (guide section 4)."
- `output`: "A 1 x 256 matrix: too narrow for Muon (fewer than 64 rows), so it takes the sign step, scaled by 1/sqrt(256)."
- every other row: "An ordinary hidden matrix: Muon, as intended."
The step line reads "Step per weight at lr 1e-2: <value>" (2 significant digits), or "not worked out in the guide" for colnorm.

"What's real here" content:
- Computed live: the routing, by our optimizer's own rules (copied from its source, 2026-10-27) applied to the real parameter
  names of one of our heads; the step per weight, as arithmetic from each group's scale.
- From our own runs: every modular run of these heads used the routing in the first view (routing check of 2026-10-17). Its
  effect on training is not measured; changing it means new runs.
- Illustration only: the renamed names are hypothetical, what a fixed rule would see; renaming the time-embedding layers is
  our reading; the step sizes leave out momentum and our optimizer's row normalisation (which makes wide matrices 2 to 3.6
  times larger, guide section 4); the moving dots are decoration.

commit it (only `routing.js` in `site/help/viz/` is committed). The stub may hard-code the fixture's results.
