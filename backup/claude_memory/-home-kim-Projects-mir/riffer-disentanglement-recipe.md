**Disentanglement-by-augmentation recipe** (user's idea, 2026-06-26 — it resolves the BPM-norm blockers I'd raised):
- **Pitch-shift augmentation** (same density+rhythm, varied pitch) → teaches density ⊥ pitch. Works with any target.
- **Time-stretch augmentation** decouples BPM **only with the onsets/beat (BPM-norm) target** — onsets/beat is stretch-invariant, so stretch varies BPM while holding the target constant → teaches onsets/beat ⊥ BPM. With raw onsets/sec, stretch COUPLES density+BPM (both scale) and *reinforces* the learned tempo-shortcut — don't pair stretch with raw density.
- Crucially, stretch-augmentation **fixes the two objections I raised against BPM-norm**: (1) the data's onsets/beat↔BPM anti-corr (−0.83) — augmentation decorrelates it; (2) Goa's narrow BPM range (which made BPM-norm premature) — augmentation artificially broadens BPM. So **BPM-norm becomes viable on Goa-only, without waiting for the genre expansion.**
- **Full recipe: onsets/beat target + time-stretch aug + pitch-shift aug = clean disentangled density control.** Tools exist in mir (bungee time-stretch binding via `bungee_python` — `Bungee(sr,ch).set_speed(ratio)` for tempo, `.set_pitch(2**(st/12))` for pitch; see `pitch_shifter_gui.py`); cost is re-encoding augmented audio → SA3 latents.

**VALIDATION (2026-06-26 — caught before the full run):** the **−8/+16 BPM augmentation is too mild to decorrelate**. Training-data corr(onset_per_beat, bpm) = **−0.81**; augmenting 25% at ±10–16 BPM only moved it to −0.805 (the shift is tiny vs Goa's ~60-BPM natural span, std 38). Meaningful decorrelation would need **±30+ BPM + ~100% coverage** (heavy stretch → quality cost, doubled dataset). So the **augmentation is a weak helper, not the fix** — the structural fix is the **`onset_per_beat` TARGET itself** (tempo-invariant → blocks the *forward* "raise-tempo-for-density" shortcut with no aug at all). **Pivoted: test the target ALONE first** (Fusion 10ep, `--scalar-field onset_per_beat`, no aug, `onset_Fusion_opb_10ep`); widen the aug only if the *inverse* shortcut (from the −0.81) shows in the output. The bungee augment→re-encode **pipeline is built & validated** (150-crop slice on Mantu, latents (256,4096) fp16, BPM moves verified) — reuse it if widening is needed. SA3 AE re-encode: `from stable_audio_3 import AutoencoderModel; ae=AutoencoderModel.from_pretrained("same-l"); ae.encode(audio_[1,2,N], sr)` → (256,4096).

**RESULT (2026-06-27): the disentanglement is a LEARNED TRANSITION, and a +50% LR (1e-4→1.5e-4) is PRODUCTIVE, not drift.** Across-epoch eval (lr1.5e-4) of opb-control vs tempo-shortcut: **ep5 = shortcut +0.68 / control −0.42** (still faking density via tempo, control inverted = onset_density-baseline behavior); **ep10 = +0.14 / +0.68** (flips to honest control); **ep14 = −0.29 / +0.60**. So the model TRANSITIONS from cheating→honest onsets-per-beat control between ep5–10. ⇒ (a) honest control is *acquired*, needs ~10ep+ (the lr1e-4 10ep test barely caught it, control +0.37 @ gain2); (b) the higher LR's faster weight-movement is productive — authority climbs ep5→14 while the shortcut stays dead (no re-entangle / "deep-fry" — answers "can high LR break weights invisibly to loss": for a FROZEN-DiT adapter the priors are protected; the analog failure is control-entanglement/over-steer-incoherence, both measurable via tempo-shortcut + groove, which is what the eval checks). **LR diagnostics (cheap, weights-only):** per-epoch ‖ΔW‖ decays smooth-monotonic 6%→2.4% (ep1→14, still moving = LR used, not plateaued); movement scales ~linearly with LR (1.5× LR → **1.42×** movement, NorMuon damps ~5% → why +50% was painless). **Operating insights the metrics hide:**
- The musically-useful low-density output is a **sparse laid-back beat, NOT an ambient drone** — measured-density can't tell them apart (both read low). Eval needs a beat-presence/groove signal, not just onset count.
- **Gain×density operating ridge (inverse):** low density wants gain ~2–3, density 12 works at gain 1 with no degradation — the model spans laid-back→fast along this ridge. The operating recipe is a *gain-per-density curve*, not a fixed gain (mechanistic: stripping to sparse needs more authority; reaching busy needs less).
- **Density is 2-D; the control is 1-D.** `onset_density` (onsets/sec) is *horizontal* density (rhythmic rate). Perceptual density also has a *vertical* axis — polyphony/layering: two overlaid syncopated 16th ostinatos are far denser but register ~the same onset rate. The control can't touch the vertical axis. For the in-context stripping tool a busy A-part is dense on BOTH axes, so `onset_density` alone may thin the rate while leaving the layers. **Open work:** measure a vertical proxy (spectral entropy/flatness, multiband-energy spread, per-stem onset spread — dataset already has multiband RMS + per-stem onset densities; true polyphony needs multi-pitch) and check on existing clips whether steering onset_density also moves it (confound) or not (a second knob to add). Long-term: a 2-D density control or a fused "perceptual-density" target.

## Goa baseline (dataset-relative Audiobox) — 2026-06-26
Audiobox must be judged vs the **dataset** baseline, not absolute (genres differ). **Precomputed Audiobox already exists** in the goa_crops `.INFO` files and the Lehto/latents (SAO-Small 256-frame) companions — use those, not a fresh sample. Full Goa baseline (**n=202,069 crops**, ~40/track): PQ 7.60, CE 6.11, CU 7.46, **PC 5.81** (median PC 5.97). Surprise: Goa PQ is *high* (~7.6, not lo-fi-low) — Audiobox does NOT hear 90s-vinyl/Fostex Goa as low quality; the aesthetic lives in **PC (production complexity), NOT PQ**. **Fusion is closer to the Goa baseline than AdamW (Euclidean 0.71 vs 0.97), driven by PC**: Fusion PC 5.50 is 0.32 off Goa, AdamW PC 5.07 is 0.74 off (2.3× further). Quantifies the Fusion preference: Fusion natively inhabits the Goa production-complexity signature, AdamW flattens it. → the eval page's score should be **distance-to-Goa**, not absolute.
