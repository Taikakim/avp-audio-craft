Ground-truth map for `/home/kim/Projects/SAO` (the mir + Stable-Audio-3 monorepo) doc audits.

## Generated vs hand-authored docs (don't trust a hand doc's freshness — check the generator)
- **`DISCOVERIES.md`** is auto-generated by `Misc/build_discoveries.py` from `profiles/*.journal.md`.
  Its own header says so ("do NOT hand-edit below this point"). **To check staleness fast: compare
  its stated entry count against journal mtimes/sizes**, or actually re-run the generator to see
  the current count — but **the script has no `--dry-run`/`--help` flag; running it WRITES the file
  for real** (confirmed 2026-08-04: it silently overwrote DISCOVERIES.md when I probed `--help`).
  If you do this, **`git checkout -- DISCOVERIES.md` immediately** to revert (this is a read-only
  audit persona — never leave a probe-induced write in place). On 2026-08-04 the checked-in file
  (dated 2026-07-06, "54 entries") was ~4x stale vs a live regen ("201 entries across 14 topics").
- **`model_index.md`** (SAO root) is a **one-time hand-compiled snapshot** ("Compiled 2026-07-04
  from Mantu/"), NOT regenerated by any script. `Misc/build_model_index.py`'s `collect_models()`
  feeds `docs/checkpoint-hall-of-fame.md` instead — a different file. **The actual live model
  catalog is `~/evals_aac/model_matrix/manifest.jsonl`** (or `manifest_live.jsonl`) — read distinct
  `"model"` keys from there for a true current count/family list. On 2026-08-04 this had 227 distinct
  model labels across entirely new families (dora128_everything_*, dora16_avp_*, bf16cmp_*,
  fp32cmp_*, fullft_*, longctx_*, xftdora/xftlora, winning_*, lreq_*, subloss_*) vs model_index.md's
  ~24 pre-07-04 entries — near-total non-overlap. Re-check this gap on every future audit; it will
  keep growing since nothing regenerates model_index.md.
- **`docs/checkpoint-hall-of-fame.md`** — Kim's manually-curated "never prune, supersede with a
  note" shortlist of ear-tested checkpoints. Legitimately allowed to look sparse/old; that's by
  design, not staleness.
- **`ARCHITECTURE.md`**'s reuse index (§ "Reusable plumbing") self-reports a **"Last full inventory
  sweep"** date near the top of that section — grep for it first. Cross-check against `git log
  --oneline -20` / `ls -la eval/ Misc/ lumi/` mtimes for tool files newer than that date; those are
  reliably undocumented. Confirmed gap 2026-08-04 (sweep dated 07-20): `build_run_audit_board.py`,
  `melody_wall_analysis.py`, `cross_attn_mask_ab.py`, `stochastic_rounding.py`,
  `goa_archive_stats_export.py`, `precision_injection_ab.py`, `build_hf_repair_pairs.py`,
  `build_clap_hyperparam_table.py` — all absent from CLAUDE/MASTER/ARCHITECTURE.

## WORKLOG.md is unusually good ground truth — check it before/instead of re-deriving
The fleet self-audits in WORKLOG and often writes explicit forward-pointers like **"TODO: log ...
to MASTER §5"** that haven't landed yet — `grep -n "MASTER §5\|MASTER.md" WORKLOG.md` near the tail
surfaces exactly the gotchas that are known-current but not yet transcribed into MASTER.md. Also
useful: WORKLOG entries frequently self-correct earlier doc claims explicitly (e.g. "X was stale,
here's the real mechanism") — these are gold for a truth audit, higher signal than re-deriving from
raw code. Tail the file (`tail -N WORKLOG.md`) and grep by date (`2026-08-0` etc.) rather than
reading linearly — it's 2000+ lines, append-only, reverse-chronological-ish but not strictly sorted.

## Known duplicate-script traps
Several tool filenames exist as **multiple, DIVERGED copies** across the meta-repo and the nested
forks — a doc's unqualified claim about "the script" may be true of only one copy. Confirmed case:
`train_latch.py` exists in 4 places (`latch/`, `stable-audio-tools/scripts/`, `onnx/latch/`,
`stable-audio-3/scripts/latch/`) with different feature sets — e.g. `--ema`/`--grad-accum` flags
exist ONLY in the `onnx/latch/` and `stable-audio-3/scripts/latch/` copies, NOT in the SAO-root
`latch/` copy that CLAUDE.md's own Layout section points readers to as canonical. **Before trusting
a doc's claim "script X does Y," `find . -iname X.py | grep -v __pycache__` across the whole SAO
tree and check EVERY copy**, not just the first hit. `chroma_losses.py` is a similar documented
(intentional, self-aware) case — MASTER §1 flags it explicitly as deliberately vendored/duplicated.

## Removable-drive mount points (check before declaring a path dead)
- Mantu → `/run/media/kim/Mantu` (source audio, checkpoints)
- Lehto → `/run/media/kim/Lehto` (training-data-only per 2026-07-04 convention)
- The "UUID drive" (canonical LUMI rsync target, per MASTER §2) → `/run/media/kim/9a410a1d-a4a8-4faf-8298-bcaa2576ea9d/`
Check with `mountpoint -q <path> && echo MOUNTED`. If mounted and a specific sub-path still 404s,
it's a genuine stale/moved path, not a mount issue — confirmed case: `Mantu/goa_crops` (documented
in MASTER §2 + ARCHITECTURE.md as a live 4829-item crop corpus) no longer exists on the (mounted)
drive as of 2026-08-04; WORKLOG:619 shows it was migrated into a SQLite DB (`mir/data/timeseries.db`,
~209k rows) around 2026-06-29, and the Mantu-table doc entry was never removed/updated after.

## Docs that are point-in-time handoff notes, not living docs
`KIM-RETURN-NOTES.md` reads like a dated action-item snapshot written for one specific return event
(has a "PASTE QUEUE" of literal shell commands + a "DECISIONS WAITING ON YOU" section). It is NOT
kept in sync after Kim returns — check WORKLOG for entries dated after the note's own date; if
WORKLOG shows the queued actions already executed-and-resolved (with a verdict) and/or explicit
"KIM DIRECTIVE"/"Kim:" quotes from after the note's date, the whole note is dead weight that should
be archived or deleted rather than left at repo root where a future instance could mistake its
action items for pending work. Don't nitpick individual stale lines in a doc like this — flag the
whole thing as one finding (superseded snapshot).

## Spot-check confidence — claims that HAVE checked out accurate (2026-08-04 audit)
These held up under direct code inspection, so treat MASTER.md's §5 gotcha ledger as generally
reliable on the *mechanism* claims even when specific numeric defaults drift (see below):
`cfg_interval` default `(0,1)` in `stable_audio_3/models/dit.py` (~L376/493); `SA3_SDPA_CAST_BF16`
env gate in `transformer.py` (~L742); `latch_guided.py`'s DiT forward wrapped in `torch.no_grad()`
with autograd only through the head (`.detach()`/`.requires_grad_(True)` pattern, confirmed lines
150-310); base model ids `small-music-base`/`medium-base` exist in `model_configs.py`, no
`small-base`; NVMe `latents_sa3` file counts (5401 `.npy`, 5400 plain `.json` — note there's ALSO
5400 `.TIMBRAL.json` sidecars that inflate a naive `*.json` glob to 10800, don't be fooled — 5401
`.TIMESERIES.npz`) match MASTER §2's claim almost exactly.

**Numeric defaults DO drift even when the surrounding prose is accurate**: MASTER §4's
"Control-response eval specs" bullet claims `onset_eval.py` defaults to `--gains
{0.5,1,2,3,6,8,12} × --densities {2,4,6,8,10,15,20}` — the live script's actual argparse defaults
are `--gains "0,1,2,4"` / `--densities "2,4,6,8,10"` (only `--duration 20` matches). Git blame traces
the claim to commit d602cf6 (2026-06-27) and it was never re-verified against the script since —
this class of "specific number embedded in old prose, script defaults changed silently" is a good
thing to spot-check on any MASTER.md bullet that cites literal default values.
