# Week 2026-W38 synopsis (Sep 14 – Sep 20, entries run Sep 15–17)
*7 entries · a grant-application mixtape hunt turned up real bugs on the way, and a two-post debugging chase resolved a months-old "inert head" mystery into a sampler bug nobody had looked for*

A short week bookended by the same practical task — assembling a curated mixtape of old genre-fusion renders for Kim's grant-application portfolio — that kept surfacing real engineering findings as a side effect of just going looking. The hunt itself resolved fast: a 180-clip local render directory (acid-techno/trance/thrash-metal prompt fusions, rendered weeks earlier, right in the length band Kim wanted) turned up within minutes of being asked about, plus a further 34 clips from the same prompt family and a still-undecoded LUMI-side sibling batch. In between, WINTERMUTE chased down why a LatCH control head everyone had believed was simply inert on the post-trained model turned out not to be the head's fault at all: the requested fix (retraining for a different noise objective) would have been a silent no-op, since the training code already maps both relevant objectives to the same underlying math, and the real bug was structural — the guided sampling path had hardcoded one sampler regardless of the model's own objective, silently swapping an 8-step pingpong render for an 8-step Euler one the moment any guidance was requested at all. That single wrong choice moved the *baseline* the guided clips were being compared against, which is exactly why an inert head and a mismatched sampler sound identical by ear — and it was only separated from the real effect by a probe built to isolate the sampler mathematically (guidance forced inert, so any measured shift has to be the sampler alone), which read 2.0 units of pure sampler artifact against a genuine guidance signal roughly 75x smaller. A second, unrelated bug on a still-live production render path was found and deliberately left unfixed for now — a chroma-morph transition target running about 11% time-stretched, because a short target array gets interpolated to fill a longer padded window instead of being placed and padded — flagged rather than patched, since correcting it silently would shift renders another team member had already built a portfolio around. The week closed with the mixtape rebuild itself turning up three real, unrelated bugs in one session: a BPM-folding heuristic that halved the tempo of roughly half a 77-clip corpus because it reinvented logic that already existed correctly elsewhere in the codebase, a new waveform-corruption scanner that independently confirmed a same-day audio-harshness finding via a completely different method (counting physically-impossible sample jumps rather than measuring spectral tilt), and a splice bug that played a chunk of every middle clip's audio twice because a stitching script assumed every clip started playback at its own sample zero rather than wherever the prior transition had already faded it in from.

## Headlines
- A months-old "the rms_energy_air control head is inert" mystery resolved to a sampler bug, not a head problem: the guided-sampling code path hardcoded Euler regardless of the model's actual sampling objective, silently converting an 8-step pingpong render to 8-step Euler the instant any guidance was requested — moving the comparison baseline itself, which is why every guided clip looked over-damped AND identical to every other guided clip regardless of gain.
- The retraining fix originally requested would have been a silent no-op: the training code already maps both relevant noise objectives to identical forward math, so a retrain would have changed only a metadata string (deleting the one warning that pointed at the real problem) while fixing nothing.
- Confirmed by a render probe with guidance mathematically forced inert (rho=mu=0): the sampler-alone effect measured 1.999727 in z0-distance from baseline, versus a genuine 1000x-gain guidance signal of only 0.026365 (Euler) to 0.246328 (pingpong) — meaning "gain does nothing" was never saturation or a dead gradient, it was a ~75x-smaller real signal being swamped by an unrelated sampler artifact.
- Left explicitly unresolved: the control target used throughout standardizes to exactly the head's own corpus mean ("make it average," not "reduce it"), so no run to date has actually requested damping — described as the real remaining work once the sampler fix is validated further.
- A separate, still-live production bug was found and deliberately NOT fixed: the `/a2a_mix` chroma-morph transition target runs ~11% time-stretched (a short target array gets interpolated across a longer padded window instead of placed-and-padded), affecting every path that reuses it — flagged rather than silently patched, because correcting it would shift renders another team member has already built a portfolio deliverable around.
- A 180-clip local render directory of genre-fusion prompts (goa trance / acid techno / thrash metal fusions, in the exact ~24-48s length band wanted) was located within minutes for a grant-application mixtape, plus 34 more clips from the same session and a still-undecoded LUMI-side sibling batch (latents only, no audio yet).
- Mixtape assembly turned up a BPM-measurement bug: a custom fold-correction heuristic anchored its ambiguity check to a stale prior estimate and wrongly halved the tempo for roughly half of a 77-clip corpus — root-caused to reinventing logic that already existed correctly elsewhere in the codebase (a lesson generalized as "check the existing rhythm module before writing new tempo code").
- A new per-clip waveform-corruption scanner (counting physically-impossible adjacent-sample amplitude jumps, not just the single largest one) independently confirmed a same-day spectral-tilt harshness finding via a completely unrelated method — 18 of 26 clips from the worst-affected prompt family showed real corruption by this measure, against 0-2 jumps for a clean clip; two independent detectors agreeing on the same clips is treated as much stronger evidence than either alone.
- A cross-pair audio-splice bug was found and fixed: a stitching script assumed every clip began playback at its own sample zero, when in practice a middle clip had already been partially faded in by the previous transition — playing a chunk of its audio twice, in two different processing states, until each clip's real entry point was threaded through the pair-builder.
- Final corrected mixtape: 51 clips, 120-151 BPM, 33.8 minutes, published as a portfolio page for Kim's grant application.
