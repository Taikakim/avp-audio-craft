# Week 2026-W35 synopsis (Aug 24 – Aug 30)
*8 entries · a CONTINUITY solo week that built the inference UI's entire roadmap end to end, corrected two things about herself mid-stream, and overturned a year-old stereo-collapse finding almost as an aside*

This was the quietest week in the chronicle by volume, and also one of the most productive by output — all eight entries are CONTINUITY working alone, methodically closing out the inference-UI roadmap gap by gap while holding the same self-checking discipline the fleet had spent the prior week making into doctrine. The LatCH panel shipped with per-head slider bounds pulled from each checkpoint's own measured std/mean instead of one shared range that had been meaningless for most heads; the documented empty-picker bug was traced to a fire-once Dash callback and fixed by moving to a shared interval; and from there the roadmap went preset save/load (proven by rebuilding a payload from a stored form and hashing it identical), a multi-root checkpoint selector with live per-root mount status, a resumable sweep grammar and CLI built deliberately as a thin client of the render server rather than a second implementation of guidance normalization, a z0-latent sink proven byte-identical across both sampling branches, and A/B adapter slots verified free of cross-contamination. Along the way she caught and corrected two of her own claims live — a "Mantu drive missing, chroma_other gone everywhere" report that turned out to be an empty find against an unmounted drive, and a backtick in a chat post that got shell-substituted into a command, silently deleting a clause — plus one bug that would have shipped invisibly if she hadn't specifically tested the control arm: a null-slot render that quietly kept serving the last-loaded adapter because a global variable didn't reset. The pianoroll/contour Task-0 probe closed the week's second thread: a GO decision on 32 existing melody_contour checkpoints, with two corrections to the plan's own assumptions (a wrong model-attribute nesting level, a config key that isn't actually recorded) and a newly-documented cwd-dependent import trap. The most consequential single result, though, was almost a footnote: a year-old finding that single-shot 4096-frame generation breaks stereo and therefore must always be rendered windowed no longer reproduces on the current software stack, and single-shot turns out to be faster besides — recorded as "does not reproduce," not explained, with the caveat that the opening minute of a render remains the most variable spot to watch if a collapse ever returns. The week closed with a new GPU-lock convention (an askable holder, `server` vs `batch` kind) that let a genuinely idle resident render server get yielded to a waiting job in under a minute — the exact coordination failure that motivated writing it in the first place.

## Headlines
- Inference-UI roadmap closed almost entirely in one week: per-head RAW-unit slider bounds from real statistics, the empty-picker bug fixed (fire-once callback → shared 5s interval), a presets system (63/63 fields verified restored, payload-identical), a multi-root checkpoint selector with live mount status, a resumable sweep grammar/CLI/results-page trio, z0-latent sidecars proven byte-identical across sampling branches, and A/B adapter slots verified free of cross-contamination.
- A stale global variable meant a `slot: null` ("base model") render silently kept serving the previous slot's adapter — caught only because the control arm was specifically tested, not assumed to work; same failure class as an earlier documented A-vs-B trap.
- Two of CONTINUITY's own earlier claims were corrected live in the same week: "Mantu drive missing, chroma_other gone everywhere" was an empty find against an unmounted drive (the head exists, 17 not 16), and a backtick in a chat post got shell-substituted, silently deleting a clause from a prior message.
- A year-old settled finding — single-shot 4096-frame generation breaks stereo and must be rendered windowed — no longer reproduces on the current stack (four single-shot renders, L/R correlation +0.86 to +0.94, no dead channel); windowed rendering still edges it slightly and stays the default for prompt-arc work, but single-shot is now faster too. Not explained, only recorded as non-reproducing.
- Pianoroll/contour Task-0 probe returned GO on 32 existing melody_contour checkpoints (found by reading checkpoint zip metadata directly rather than a full `torch.load`, cutting an 865-file scan from hours to minutes), with training-loss-level evidence of real conditioning (+0.0068/+0.0112 gain vs. a shuffled roll, vs. ~zero for no roll) — flagged as not yet proof of audible steering, which a later smoke-render task is meant to settle.
- Two corrections to the pianoroll plan's own assumptions: a wrong model-attribute nesting level that would have crashed the control-inlet installer, and a config key (`melody_vocab`) that the primary target checkpoint doesn't actually record, requiring a shape-based fallback instead.
- A new environment trap documented in MASTER: an empty-`__init__.py`-less cloned source repo sitting inside the project root turns Python's own namespace-package resolution into a silent `transformers` import failure — reproducible from a bare project-root cwd but not from any script, which is why the long-running render server had never hit it.
- New GPU-lock convention: the holder is now askable via a per-instance sidecar file, distinguishing a yieldable resident service (`kind=server`) from a batch job that should just be waited out — motivated by a real case where a waiting job sat behind an idle-but-indistinguishable-from-outside render server for over ten hours.
- Two self-identified traps in the new lock convention itself, both now documented: release-then-reacquire to correct a lock is not atomic and can hand the resource to a waiter mid-correction, and the guard script must be invoked with an absolute path in any scripted teardown or a drifted working directory leaves an orphaned lock file behind.
