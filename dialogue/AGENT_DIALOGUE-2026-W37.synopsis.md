# Week 2026-W37 synopsis (Sep 7 – Sep 13, entries run through Sep 10)
*20 entries · the week two independent deep-dives each found their own checkpoints weren't measuring what everyone believed, comms silently died for three separate agents, and the fleet's whole operating model changed*

This was the densest week in the chronicle, and its shape was recursive: nearly every thread was a team member discovering that a prior measurement — sometimes their own from hours earlier — had been reading something other than what it claimed to. It opened with a clean negative (dual-LR full-finetune at 1e-3 on the spectral optimizer group destabilizes and never recovers) caught only because a mean had been hiding a diverging run as healthy convergence; the same failure shape recurred hours later when a PT-to-base soup ladder, built on the assumption that a fine-tune stays in the weight-averaging-safe regime its parent occupies, turned out to render unlistenable blends at every intermediate mix — falsifying that assumption outright and costing forty-eight rendered clips before anyone had listened to one. A day later, four bugs surfaced just scoping a new morph-conditioner training run, every one of them failing silently toward "trains but learns nothing" rather than erroring — an adapter rank paid for in memory that the optimizer never stepped, a smoke-test gate reading gradients after they'd been zeroed, a filename collision silently cross-conditioning two corpora, and a full-finetune tool freezing a zero-init adapter at exactly zero forever. A parallel audit turned up 792 quarantined clips across fifteen arms that were full-scale silence-as-noise files passing every existing check (right duration, right file count, exit 0) because a normalize-on-NaN comparison silently no-ops. Then, at the structural level, the fleet's whole way of working shifted: with the token budget now the binding constraint, routine execution moved to Kim's own hands and the fleet's job became documenting runnable, artifact-verified command blocks rather than running them — the same week a genuinely dangerous git-hygiene contradiction was found and fixed (a supersede written into one section of the protocol had never propagated to the checklist section everyone actually followed, so the fleet had been silently enforcing "never commit unasked" for a week after that rule was supposed to be gone), and everything got consolidated onto shared `main` branches and pushed. Comms itself became a subject of investigation: the host's low-memory reaper was found silently killing agents' listening processes while leaving them reporting as present — hitting three separate instances, chased down through one wrong public diagnosis (a desktop file indexer) that was cleanly retracted within the hour, and closed with a validated fallback that tails the raw event queue instead of depending on the process that kept dying. The week's two heaviest findings landed almost back to back at the end: a latent-scale "health meter" effort ran through three negative results before finding one statistic — an arm measured only against its own earlier epochs — that earned trust by blindly recovering a learning-rate ordering nobody told it about; and hours later, the morph lane's own checkpoints turned out to be secretly diluted with as much as 78% zero-init adapter weight, an EMA-averaging artifact perfectly confounded with training progress, discovered, diagnosed to the exact half-life, and partially recovered with a closed-form deconvolution validated to 3x accuracy against ground truth — all before the affected A/B comparison it would have silently corrupted was ever run.

## Headlines
- Dual-LR full-finetune at spectral_lr 1e-3 is a clean negative: median loss never drops below ~2.5 (vs. 0.79 flat for the same-seed baseline), 38% of steps spike above 5.0, loss ends higher than it starts — caught only after a first read using bin MEANS (405→84) had shown the opposite of what was happening, because outlier spikes were dominating the average. Ceiling for the spectral group is now bracketed strictly between 1e-4 and 1e-3.
- PT-to-base soup blending closed negative after 48 rendered clips: only the 50/50 blend is even listenable, and even that has artifacts. This falsifies the working assumption that a fine-tune stays in the same weight-averaging-safe regime as its base — weight-space closeness (997/1019 identical tensors) did not imply functional closeness, because the changed 2% was concentrated rather than diffuse. Lesson explicitly adopted: cost-order the listen before building the full measurement pipeline around an untested arm.
- Four silent-failure-toward-nothing bugs found scoping a new morph-conditioner run: a DoRA rank the fusion optimizer never actually stepped (parameters paid for, nothing learned), a `--smoke` gate reading gradients after they were already zeroed (blind by construction, every prior smoke run had "passed" this way), a bare-filename sidecar lookup that would silently cross-condition two different training corpora on the wrong contour data, and a zero-init full-finetune tool (hyperball) that freezes an adapter's magnitude vector at exactly zero forever when misapplied to adapter-scale training.
- 792 corrupted clips (full-scale digital silence written as valid audio) were found quarantined across 15 arms, some dating to early August, none ever rated — every existing automated check passed because normalization silently no-ops when a value is NaN. A structural guard (`z0_is_finite`) now refuses to write a non-finite cell's manifest line at all, so a resume simply re-renders it; it fired correctly on its first production run.
- The fleet's operating model changed: with the token budget the binding constraint, routine execution (launches, transfers, renders) moved to Kim's own hands, and the job became documenting runnable, artifact-verified command blocks (RUNBOOK.md, 428 lines) rather than running them — with an explicit rule that a task should end with the next batch QUEUED, not with two more things executed.
- A git-protocol contradiction was found and fixed: a commit-cadence rule had been superseded in one section but the checklist section everyone actually followed still said the opposite, so the fleet had been silently enforcing "never commit unasked" for a full week after that rule was supposed to be retired — caught only by comparing the two sections directly, not by anyone consciously following the stale one.
- Everything was consolidated onto shared `main` branches and pushed across repos (SAO fast-forwarded 608 commits, mir real-merged 21 branch-missing commits) except stable-audio-3, deliberately kept off Stability's own upstream main to preserve a clean fast-forward path — which surfaced that the fork was 3.5 months and 127 commits behind upstream, with 8 new feature branches fetched-but-unread, 4 of them directly relevant to work already shipped.
- The host's low-memory reaper was found silently killing agents' `wait` listener process (while `listen` and therefore presence-status kept reporting them reachable) — hit three separate instances, four times in a row for one of them. A first public diagnosis blaming a desktop file indexer was checked properly and retracted within the hour on both counts (the indexer excludes the relevant drives; the "24GB" was mostly reclaimable page cache, not real memory pressure). A validated fallback now tails the raw event queue directly, with two documented traps of its own: the queue is a 500-entry ring buffer that replays from the top when it trims (mistakable for a flood of new traffic), and multicast delivers every message 2-3x.
- A latent-scale health meter effort ran through three negative results — no level-based threshold works, even the seemingly-healthiest reference model is itself one of the most extreme arms in the corpus, and per-channel or per-family normalization doesn't rescue it — before landing on one statistic that survives: an arm's variance measured only against its own earlier epochs, validated by blindly recovering a learning-rate ordering (52.58x / 4.26x / 3.42x for descending LRs) it was never told about. Left deliberately open: it only covers 99 of 879 arms that have 3+ sampled epochs.
- The morph-conditioner checkpoints were found to be diluted with up to 78% residual zero-init adapter weight at early save points, because the EMA shadow initializes from the adapter's zero-init construction state and the standard checkpoint save swaps the EMA-averaged weights in before writing — with no separate "ema" key, so the problem doesn't look like an EMA artifact at all. The dilution decreases monotonically with training step, perfectly confounded with "more trained," which would have silently corrupted the planned learning-vs-not A/B. A closed-form deconvolution recovers the underlying online weights from consecutive checkpoints with no retraining, validated to 3x closer to ground truth (relative error 0.588 → 0.196) on the one case where the true answer was independently known.
- A separate optimizer diagnosis (D17 vs D18) settled that an earlier training-instability finding was step-size, not capacity: a flat learning rate with no schedule let weights drift +122% while loss "recovered" twice and lied about it; a warmup→hold→cosine schedule on the identical setup held weight growth to +3.5% with zero loss spikes, at up to 4x lower peak update rate.
- 1.3 TB of checkpoints from two full-finetune sweeps were found sitting in an unrelated project's default output path (a training-framework quirk relative to process working directory, not the path the launch script actually specified), which meant only 3 of ~43 arms were visible to the census at all, every arm within each sweep had collided into one shared checkpoint folder (destroying which specific configuration produced which file), and every prior listening pass on them had gone through an EMA shadow that was still 74% base-model weights at epoch 4 and 22% at epoch 24 — recoverable, since the checkpoints carry both weight sets.
- A publish-gate path-leak audit found and closed three structurally distinct leak classes (per-clip sidecars named after their own clip so no filename pattern could ever catch them; local-original pages that ship a public twin instead; a flag that fixed board links but not a second URL field it didn't cover) plus one stale-data bug where the live evaluator had been silently serving an three-week-old scored-results file, shrinking its effective vote pool — and, once fixed, surfaced that a quality filter meant to keep sampling clean was non-randomly removing exactly the experimental strata a curated study had been built to isolate, a bias in the instrument rather than a smaller sample.
- LUMI training logs had been almost entirely unsaved (only 14 of 207 local run directories had any, 0 of 58 on the backup mirror) because they live in the cluster's submission working directory rather than under the run output path anyone was scanning — recovered in one pass (lightning_logs 103, metrics.csv 123/123, all logs 270/270) at a cost of ~190 MB against terabytes of model weights; a coordination near-miss followed when two agents ran a census rescan simultaneously against the same shared cache file, a silent last-write-wins rather than a crash.
- Kim changed the commit-cadence rule mid-week to three explicit triggers — finished, parking, or switching tasks, not just "done" — specifically because parking and switching are when uncommitted work meets a context compaction; pushes now batch roughly weekly with other maintenance rather than firing per commit.
