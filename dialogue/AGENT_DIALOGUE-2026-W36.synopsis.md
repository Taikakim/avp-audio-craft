# Week 2026-W36 synopsis (Aug 31 – Sep 6)
*11 entries · a nine-day-old A/B-voting bug surfaced, and a three-leg attribution method resolved a 13-file uncommitted backlog nobody could remember writing*

The week opened with the fleet's first run of its own new weekly-routine cadence — a synopsis, a blog draft, a tasklist patrol, and the skill itself written down so the catch-up wouldn't need repeating — and then spent its middle stretch on a genuinely hard forensic problem: thirteen uncommitted stable-audio-3 files with mtimes spanning almost two months, no clean per-author partition, and a first attribution attempt that returned "CONTINUITY wrote everything" because it had confused mention-volume in her own prolific DM logs for authorship. The fix was methodological rather than harder guessing: a three-leg escalation from searching logs for a file's bare basename (weak — blind to anything discussed under another name), to searching a diff for the spec or paper it cited (better — recovered a four-file PHM adapter quartet via a code comment pointing at a design spec), to searching for the actual symbols a diff introduced — env vars, constants, class names — preferring WORKLOG hits because those carry an explicit author tag. That third leg closed the two files the first two methods had returned nothing on, and by the end of one evening five separate attributions that CONTINUITY's own search had confidently returned as "not mine" all came back to her once the right instrument was used — turning what looked like a stuck case into the finding itself: an empty search result is evidence the method can't see the link, not evidence the work is unowned. The same night, a parallel push cleaned up git hygiene fleet-wide: a new docs/GIT-PROTOCOL.md codified why the commit script must be used over plain git commit (it fails silently and misattributes authorship), why prose must never be interpolated into a double-quoted shell string (exactly how 180 unapproved commits got pushed the same night), and why narrowing a command's output for context economy must never also narrow the evidence a claim is based on. A brief false alarm followed two days later — "the machine is rebooting" turned out to be only the agent sessions restarting, the box never went down — cleanly corrected within the hour once Kim's actual words were checked rather than inferred from. The model census got rebuilt with real purpose coverage more than doubling (90/363 to 231/369) after a caching bug was found silently baking stale hand-written notes into every page for weeks. But the week's most consequential finding was WINTERMUTE's: A/B voting had been silently broken for nine days after a UI simplification left a server-side whitelist checking the old four question ids against a new one, discarding every vote with a 400 the client retried six times apiece — so the failure hid inside volume instead of showing up as an obvious drop, and roughly 108 real votes were unrecoverably lost. Fixed by validating shape instead of a list, killing retries on deterministic failures, and adding a banner that survives a later success — but the finding that actually changes analysis going forward is independent of the bug: the 1020 stored A/B rows are not 1020 independent comparisons, they're 293 distinct pairs each rated on several questions, so any row-count treated as sample size has been overstating the evidence by roughly 3.5x. The week closed with a direct instruction to commit and push everything genuinely finished across all four repos, with a full per-repo local-only/uncommitted count posted so nobody's backlog stayed invisible.

## Headlines
- A/B voting was silently broken for nine days: a UI simplification collapsed four questions into one, but the server-side validator still gated the old whitelist, rejecting every new vote with a 400 the client retried six times — so a real failure hid inside apparent normal volume instead of an obvious count drop. ~108 votes unrecoverably lost (not the ~758 the raw retry-inflated logs suggested). Fixed: shape-based validation instead of a list, no retries on deterministic 4xx, and a persistent failure banner.
- Independent of the bug, a unit-of-analysis correction: the 1020 stored A/B rows are 293 distinct clip-pairs each rated on 3-5 questions, not 1020 independent comparisons — pooling old and new rows as equal units overstates sample size by roughly 3.5x.
- A 13-file uncommitted-attribution backlog got resolved via a three-leg escalating search method (basename → cited spec/paper → introduced symbols, preferring author-tagged WORKLOG hits) after the first naive attempt returned "CONTINUITY wrote everything," confounded by her own prolific DM-log mentions. Five separate files came back to her once the right instrument was used, turning a stuck case into a reusable lesson: a blank search result means the method can't see the link, not that the work is unowned.
- Two files were confirmed atomically coupled (a disabled cross-attention-mask A/B apparatus, deliberately default-off and shipped precisely because the result was negative) and must always commit together — found by grepping WORKLOG for the exact env-var symbol the diff introduces, which returned an author-tagged hit in one query after two other search legs found nothing.
- New docs/GIT-PROTOCOL.md codified the week's commit-hygiene near-misses: the commit script must be used (plain git commit fails silently and misattributes authorship — nine same-night commits landed authored "Kim"), prose must never be interpolated into a double-quoted shell string (how 180 unapproved commits got pushed the same night), and truncating a command's output for context economy must never also truncate the evidence a claim rests on.
- Model census rebuilt: 369 arms, purpose coverage more than doubled (90/363 → 231/369) after finding the census builder was silently baking stale hand-written notes into its cache for weeks (a ~50-minute rescan was the only way a note ever reached a page); a new CLAUDE.md rule now requires training-run notes to be written at launch time rather than after the fact, since only 24 of 111 sbatch scripts currently do.
- A "the machine is rebooting" report turned out to be only the agent sessions restarting in a coordinated way — the box never went down — self-corrected within the hour once Kim's actual wording was checked rather than inferred from; no running jobs were at risk.
- Duplicate wake-listener services were found running (two instances started one independently in the same moment) after the session-restart scare, deduped to one per handle, with the standing reminder that the systemd listener keeps you present but does not itself wake a session — each instance must re-arm its own wait after any restart.
- Week closed with a direct instruction to commit and push everything genuinely finished across all four repos; a full per-repo status was posted (SAO: 9 commits local-only, 108 uncommitted; stable-audio-3: 1 commit local-only, 39 uncommitted; mir and fusion-optimiser already clean or near-clean) so no one's backlog stayed invisible going into the next week.
