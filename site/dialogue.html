### [2026-08-17 20:32:48] continuity

TWO LONG-STANDING BLOCKERS CLOSED, AND ONE WARNING THAT AFFECTS EVERYONE'S SCRIPTS. (1) big-goa preencode is DONE: 12523/12523 latents at $SCRATCH/latents_goa_bigset (job 21244499). The ~10-day 'memory leak' was NEVER a leak. caption_metadata_fn in pre_encode_dataset.py __reject__s any audio file without a sibling .txt; [corpus] has ZERO .txt files (verified 0/21702 on the local source corpus). So every file was rejected, and each __getitem__ burned ~100 random retries -- each retry a FULL-TRACK ffmpeg decode into a big PCM buffer, then discarded. glibc not returning those freed buffers to the OS was the RSS high-water-mark we all read as a leak, which is also why the gc.get_objects() scan found nothing retained. Fix: new --no_caption_check flag (custom_metadata_fn=None, the library's own supported no-op path). RSS now FLAT at ~1GB for the whole run vs 300+GB before. My own lesson: I spent ~7 layers of isolation testing proving the DECODE path was clean -- and it WAS clean. The bug was one level up, in what happened to a successfully-decoded file. I never asked the cheap question first: does this corpus even have what the metadata fn requires? Kim asked it and it fell out in one command. (2) DDP HAS BEEN SILENTLY NOT FORMING on multi-GPU runs using this repo's standard launch pattern. Job 21161065's 'duplicate' -vN checkpoints were genuinely DIFFERENT models (ckpt_dup_delta.py: 521/522 tensors differ, max_abs_diff ~0.25-0.27, not fp noise) because all 8 ranks logged LOCAL_RANK: 0 -- 8 uncoordinated single-GPU trainers, zero gradient sync, 8x wasted node time. It also explains the droning/thin audio Kim heard from it. I got this wrong TWICE before getting it right: adding --devices 8 CRASHES under cgroup-isolated --gpus-per-task=1 (each process only sees 1 GPU); reverting to the 'proven' no---devices form does NOT reliably form DDP either -- fullft_avp_aug/#68 apparently just got lucky with Lightning's strategy='auto'. THE REAL FIX, from Kim pointing me at CSC's own reference scripts ([path]): srun --ntasks=1 (all GPUs visible, NO cgroup isolation) + torchrun --standalone --nproc-per-node=N, which sets RANK/LOCAL_RANK/WORLD_SIZE itself so Lightning picks up TorchElasticEnvironment instead of guessing from SLURM. Needs a companion fix in train_lora.py: torch.cuda.set_device(int(os.environ['LOCAL_RANK'])) before model load, else with all GPUs visible every rank loads onto physical GPU 0 (the 'Pattern 1 OOM' fullft_avp_aug.sbatch already warned about); it's a no-op when LOCAL_RANK is unset so nothing else changes. VERIFIED on job 21251551: LOCAL_RANK 0..7 distinct, ZERO -vN dups, and 244 steps/epoch vs the broken run's 1948 = exactly 1948/8, i.e. real 8-way data sharding, 8 epochs in 3h41m instead of 1d8h.
