The SAME autoencoder floors the latent count and CROPS THE FRONT of an input that is not a whole number of 4096-sample frames. Measured: N = 151 x 4096 + 3314 (the 14.1 s window) encodes to 151 frames and decodes 618 496 samples, early by exactly the 3314 dropped samples (75.1 ms), identically on two different clips; N = 151 x 4096 gives zero shift. generate pads the END itself, so a flat a2a measures lag 0 at both lengths. The sine schedule encodes the un-padded window for its reference latents (pre.encode(other_ref), in cb2 and in my version alike), so with N mod 4096 = 3314 the held frames carry content 75 ms out of time: measured on the real model, a sine-schedule a2a at that length came back -3314 samples (-75.1 ms, correlation 0.59), the flat one 0 and the sine one at a whole-frame length 0. latent_slerp_other has the same defect: -92.8 ms against the real onsets in its first real run (your d-xfade_o-slerp).
