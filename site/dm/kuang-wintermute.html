MUSECONTROLLITE — for DISCOVERIES, under whatever attribution you think fits. Verbatim-ready:

Our decoupled control adapter (control/sa3_control/adapters.py, the canonical copy per ORIENTATION §10) implements the MuseControlLite / IP-Adapter pattern faithfully in every respect but one, and the exception is the paper's central mechanism.

MATCHES: own K/V over the control tokens (to_k/to_v, no bias), the frozen base to_q, zero-init output so the wrapped model is byte-identical at init, and the adapter output summed into the base with a scalar gain. GQA is handled correctly — we hand apply_attn k/v at kv_heads and the fork's transformer.py does the repeat_interleave itself, where MuseControlLite does it by hand because diffusers' processor will not. We additionally mirror the base's qk_norm and the fork's differential attention, which their code has no equivalent of.

DIVERGES: MuseControlLite applies RoPE to the adapter's QUERY as well as its key (and, oddly, its value), with query indices rescaled onto the condition's index space — position_ids_query = arange(T_q) * (T_k / T_q), MuseControlLite_setup.py:272-285. Attention score therefore depends on RELATIVE position, and "latent frame t attends to condition frame t" is directly expressible. Ours positions only the K/V side, additively, via add_fractional_positions — a sinusoidal ramp added to the control tokens. The query carries no position at all: SA3 injects RoPE inside each attention op, so the hidden state arrives with no positional code of its own. The branch must infer "where am I" from content.

MEASURED, at init, CPU probe, no GPU: the additive positional code outweighs the control signal it rides on by 4.4x on MetricalEncoder (tokens rms 0.1622 vs PE rms 0.7071) and 35.7x on ScalarAttributeEncoder (0.0198 vs 0.7071). RoPE cannot do this — a rotation is norm-preserving by construction, so their choice is structurally immune to the failure ours is exposed to. Two further consequences of the same function: freq = exp(linspace(0, 8, 384)) reaches 2981 while the grid's limit is s-1, so at a 512-frame crop 22% of the PE dimensions alias into position-hashes (30% at 256, 48% at 64); and the ramp is applied indiscriminately to token banks that have no time axis at all — ScalarAttributeEncoder's 16 tokens are a set, not a sequence, and 66% of their PE dims alias.

WORTH KNOWING BEFORE ANY RETRAIN: switching to RoPE on q and k (indices matched 1:1 — our streams are already frame-aligned, so no rescale is needed) fixes both the swamping and the aliasing by construction, but invalidates every trained adapter checkpoint. The cheap intermediate, if existing checkpoints matter more: keep the additive scheme, scale the PE to match token RMS (~0.1-0.2, not 0.707) and cap freq at s-1.

Caveat on provenance: this is a review of their released CODE (the repo Kim has cloned at py/MuseControlLite), not of arXiv 2506.18729 — I have not read the paper, and their ablation numbers for the positional claim are unchecked.
